# 实验计划与执行 Agent：交接清单

文档导航：[简明使用说明](README.md) · [开工指南首页](../README.md) · [详细设计 3](../../详细设计/3_实验计划与执行_详细设计.md)。

本文交接的是“读取已批准选题 → 生成实验计划 → 本地执行 → 汇总与分析 → 提出下一步或交给写作”的软件模块。实现依据《需求分析》FR-20–32、FR-34–37、FR-62 本地部分，以及详细设计 3。未加入自定义研究创新。

**交付结论：本模块的软件功能已实现，已执行的本地自动测试及独立真实 API/GPU 验收通过，可以提交源码供组内审查。** 默认关闭的付费测试、其他同学独立复现和整个小组的正式课程评价，不能据此记为全部完成。

## 1. 实现范围与交付边界

| 流程 | 实现状态 | 主要位置 |
|---|---|---|
| 文献选题交接 | 读取引擎记录的准确获批版本，核对审批与哈希；不直接使用未批准草稿 | `stages/plan/stage.py` |
| 实验计划起草与修订 | 复用 LLMGateway；展开任务与种子；预检查失败时有限修订；提交版本审批 | `stages/plan/{stage,expand,precheck,render}.py` |
| 数据和模型准备 | 文件/模型哈希、数据划分与泄漏检查；缺失或异常时按流程等待处理 | `runtime/data.py`、`tasks/text_cls_lowres/` |
| 编码 Agent | 复用 tool_loop；提供入口、方法源码、schema 和准确的试运行编号；限制可读写路径与工具 | `stages/experiment/coder.py` |
| 静态检查与试运行 | 使用实验解释器检查语法、依赖、未定义变量；正式运行前要求通过 trial | `coder.py`、`stage.py` |
| 本地执行与归档 | 固定入口；GPU 串行；状态、日志、取消、超时、重启核对；代码/配置/输入/环境快照 | `runtime/{local,wrapper,envsnap}.py` |
| 有限失败恢复 | 错误分类、保持等效批大小的 OOM 调整、受限修复与重试；缺依赖停下来请用户安装 | `stages/experiment/repair.py` |
| 汇总与人工标注 | JSON/CSV/Markdown；均值、样本标准差、区间、描述性比较、排除与成本；保留原始记录 | `aggregate.py`、既有 `services/runs.py` |
| 结果解释与决策 | 分析 Agent 读取归档 Markdown 表；数字及证据引用核验；假设状态、异常诊断、下一步建议 | `analysis.py` |
| 计划内复现与停止 | 按批准规则补比较组种子；预算、轮次、无进展和完成条件限制后续执行 | `analysis.py`、`stage.py` |
| 审批与写作交接 | 计划、重要过程日志、计划变更保留人工审批；普通任务自动继续；最终交接到 Writing | 既有主干引擎与实验阶段 |
| 评价与复现材料 | 能力指标、成本试点、人工评分记录、英文报告草稿及独立复现包 | `eval/metrics/experiment_*.py` |

表中的 `stages/`、`runtime/` 均位于 `airesearcher/` 下。文献模块、共享 core/engine/llm 接口没有在本轮交接中改写。

按用户最终要求保留原 `config_schema.json`：不支持的方法或参数配置应停止，不允许改 schema 绕过。SSH、多 GPU、自动安装依赖及论文写作不在本模块实现范围；非 NLP 演示在设计中属于可选项。

## 2. 安装与运行入口

具体安装、免费演示、真实项目配置和审批命令按 [README](README.md) 顺序执行。以下入口从完整源码仓库根目录运行，不能只复制 `airesearcher/` 包。

| 入口 | 用途 | API / 训练 |
|---|---|---|
| `python -m scripts.experiment.demo` | FakeLLM + FakeExecutor，验证计划、执行、分析和日志 | 均不发生 |
| `python -m scripts.plan.handoff` | 使用文献同学的真实阶段实现和本地模拟输入，验证文献 → 计划 → 执行交接 | 均不发生 |
| `python -m scripts.plan.demo` | 单独验证计划阶段，停在 PlanPending | 均不发生 |
| `python -m scripts.experiment.local` | FakeLLM + LocalExecutor，显式运行本地训练 | 不调 API；真实训练 |
| `air serve` + 真实项目配置 | 生产引擎连续调度，使用已有模型配置和真实执行器 | 会调 API、真实训练 |

查看额外参数可用上述命令的 `--help`。例如免费交接测试：

```bash
python -m scripts.plan.handoff \
  --workspace "$AIR_HOME/demos/literature_experiment_$(date +%Y%m%d_%H%M%S)" \
  --task smoke --approve-test-idea
```

`--approve-test-idea`、`--approve-plan-for-simulation` 仅模拟新隔离工作区中的测试审批，不批准正式研究选题或计划。demo 不用于恢复真实项目；每次使用新空目录。真实项目从原工作区和主干检查点恢复。

## 3. 自动测试与交接检查

在已安装 `.[dev]` 的环境、仓库根目录执行：

```bash
export AIR_REAL_LLM=0
exp_test_root=$(mktemp -d /tmp/air-experiment-tests.XXXXXX)
python -m pytest -q -p no:cacheprovider --basetemp="$exp_test_root/pytest"
python -m ruff check --no-cache .
lint-imports --no-cache
python -m pip check
```

对已经运行过的目标项目检查交接格式：

```bash
air dev check "$AIR_HOME/projects/实际项目编号" --owner 实验
```

完整回归使用 FakeLLM/FakeExecutor 和标准库 smoke 子进程，不重新训练分类模型。安装了可选 SDK 时，还会用模拟响应、禁止网络的方式检查函数工具初始化。默认跳过的真实付费测试不会因上述命令自动开启。

## 4. 输入、接口与产物

正式项目默认位于 `${AIR_HOME}/projects/<project_id>/`，源码仍位于 Git 仓库；两者是文档规定的不同目录。开发 demo 可以指定独立工作区。以下路径均相对项目工作区，研究产物使用英文。

| 路径或接口 | 内容 / 下游用途 |
|---|---|
| `idea/selected.md` 及审批记录 | 文献模块提供的研究问题、假设、方法、指标、预算和引用；必须准确获批 |
| `plan/experiment_plan.md` | 含结构化数据区的英文计划；执行与写作使用同一批准版本 |
| `plan/tasks.json` | 确定性展开的运行清单、配置、种子、依赖及评价条件 |
| `plan/precheck.json` | 数据、指标、许可、公平性、预算等 pass/warn/fail 检查 |
| `runs/<run_id>/` | `run.json`、配置、代码快照、原始指标、资源、环境、状态、stdout/stderr 和输出文件 |
| `artifacts/aggregates/<comparison>.json/.csv/.md`、`all.*` | 统计表、比较、失败/排除信息、成本及证据定位 |
| `logs/round_<n>.md` | 观察、模型解释与证据等级、异常处置、假设状态、决定、成本和受影响实验 |
| `environments/data_checksums.json`、`environments/<hash>/` | 输入校验记录、依赖锁、环境信息和 `REPRODUCE.md` |
| `approvals/`、`.state/`、`.llm/` | 版本审批、恢复状态、模型调用与预算审计 |
| `airesearcher.services.runs` | 论文/GUI 复用 `list_runs`、`load_run`、`load_plan`、`load_aggregate`、`resolve_value`、`recompute_aggregate` |

论文同学应通过既有服务读取正式运行、汇总和过程日志。原始数字由包装器及确定性统计代码产生；模型负责计划、代码修改、解释和建议。`trial`、`explore`、模拟结果及被人工标为无效的记录不能混作最终 test 结论。

## 5. 配置、密钥、设备与审批

- 模型与密钥沿用 `${AIR_HOME}/models.yaml` 和同目录 `.env`。`.env` 的变量名必须与 `key_env` 一致；使用 `OPENROUTER_API_KEY` 完全可以。OpenRouter 配置需指定对应 `api_base`，不能仅把它的 Key 当作 Anthropic 官方 Key 使用。
- 正式项目需同时选择真实 plan/experiment 阶段、`experiment.llm_backend: api` 和 `allow_local_execution: true`。单独开启某一个不会自动完成其他配置。
- `exp.planner`、`exp.coder`、`exp.analyst` 复用已有 LLMGateway 和模型路由；FakeLLM 保留为测试替身，不是最终真实调用的替代品。
- 模型调用费用、预算和停止沿用主干。验收时的累计 $1 账本是该次测试专用；普通项目可设置自己的预算。主干在响应后记账，项目停止线不等于供应商预付费硬限额。
- FakeExecutor 不训练；TF-IDF 使用 CPU；全量微调/LoRA 根据批准配置使用设备。配置为 CUDA 时，GPU 不可用应报错，不能静默退回 CPU。
- 正式人工审批按需求保留。批准选题后自动进入计划，批准计划后自动执行和分析，重要日志等待人工决定；无需人为把普通任务拆成每条命令执行。
- 缺依赖时由用户安装。当前 LiteLLM 的函数工具初始化需要 MCP extra，已纳入可选依赖 `.[llm]`；没有给编码 Agent 增加安装或任意 shell 工具。

## 6. 实际验收记录（2026-10-23）

- Ubuntu、Python 3.12 的 `air` 环境；全项目最终回归 **467 passed、6 skipped、0 failed**，382.24 秒。6 项真实付费测试按默认设置跳过；有 1 条上游 Pydantic 提示。Ruff、5 项 import-linter 约束和 pip check 通过。
- 独立真实验收复用 OpenRouter Gemini 2.5 Pro，用户分别批准计划 v4 和过程日志 v2。完成 2 次 trial、6 次正式 GPU 运行：full_ft 与 LoRA，1,000 条训练样本、3 个 epoch、种子 0/1/2。
- 设备为 NVIDIA GeForce RTX 4060 Laptop GPU；PyTorch 2.14.1+cu130。正式结果的预测指标与汇总已重新计算核对。
- 本次固定实例中 full_ft / LoRA 平均 accuracy 为 0.850917 / 0.843654，平均训练耗时为 23.606475 / 14.636056 秒；accuracy 的描述性 Welch 检验 p=0.5142。三种子的小样本不支持泛化为普遍优劣或等价结论。
- 在隔离副本注入一个运行错误，真实编码 Agent 通过受限工具修复并完成 CUDA trial；真实分析调用验证了 Markdown 表输入。原八次运行、批准计划/日志哈希保持不变，原项目停在 Writing 交接状态。
- 原首轮交接的记录费用为 $0.142262；加上修复与分析对齐验证，累计记录费用为 **$0.299121**，未超过用户授权的 $1。本轮交接文档编写不新增模型调用。
- 3 个受控异常被识别，2 个正常对照无误报；用户已对 1 条历史后续建议的区分解释理由给出人工评分。这些小样本只作为验收证据。

原机器证据在 `/home/plj/air/projects/p-20261023-58db/environments/alignment/`，包括 `requirements_alignment.json/.md`、测试 XML、成本试点、复现包和英文报告草稿。该个人路径不要求其他组员具备，也不随源码自动提交。

## 7. 提交范围与诚实保留的限制

建议提交本模块源码、测试、模板、依赖声明和文档，范围包括：

| 文件范围 | 用途 |
|---|---|
| `airesearcher/stages/plan/`、`airesearcher/stages/experiment/` | 两个真实阶段及版本化提示 |
| `airesearcher/runtime/{data,envsnap,local,wrapper}.py` | 数据、环境、执行与包装器 |
| `airesearcher/testing/fake_executor.py` | 与正式运行格式一致的测试替身 |
| `tasks/text_cls_lowres/`、`skills/experiment-planning/` | 可运行演示模板、配置 schema 与计划规则 |
| `scripts/plan/`、`scripts/experiment/`、`eval/metrics/experiment_*.py` | 开发、验收与只读评价工具 |
| 对应新增/修改的 `tests/` | 计划、执行、恢复、统计、语义保护、上下文和交接回归 |
| `pyproject.toml`、`skills/registry.yaml`、详细设计 3 的配置登记、本文档目录 | 依赖、技能版本、配置说明和交接 |

以下事项明确保留：

1. 上游验收选题含模拟文献证据，真实训练不能替代文献事实核验；SST-2 许可仍有已披露警告。
2. 一个受控错误修复、三个人工构造异常和一条人工评分，不构成任意真实模型修复能力或研究质量保证。
3. 详细设计 §15.3 要求论文同学独立执行核心实验复现。源码、配置、输入版本、环境锁和说明已准备；对方实际执行与签字仍待完成。
4. §15.1 的实验模块成本已记录；组长仍需合并真实文献和写作成本，确定主对照评价轨迹数。整个小组的课程评价和论文不由本模块代办。

本模块可以作为软件交付提交；以上外部评价不能标成已经完成。
